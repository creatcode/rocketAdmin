## 定位：addtabs 刷新跳转 bug（/admin/dashboard/index?ref=addtabs → 刷新变 /admin/dashboard/index/index）
- 根因：TP5→TP6/TP8 迁移时 `redirect()` 助手语义变化。TP5 的 `\redirect()` 内部走 `Url::build()` 生成**绝对**地址（`/admin/index/index`）；TP6/TP8 的 `\redirect()` 只把字符串原样写进 `Location` 头（`index/index` 相对地址），浏览器按当前路径 `/admin/dashboard/index` 拼接 → `/admin/dashboard/index/index`。
- 代码证据：TP6/TP8 `vendor/.../think/response/Redirect.php::output()` 直接 `$this->header['Location'] = $data;`，删掉了 TP5 的 `getTargetUrl()`/`Url::build()`；`BaseController::redirect()` 仍保留 TP5 四参签名但 `$params` 被丢弃、URL 不构建。
- 对比 TP5 参考 `E:\phpstudy_pro\WWW\fastadmin`：`think/response/Redirect.php` 有 `getTargetUrl()` → `Url::build($this->data, $this->params)`，故 `redirect('index/index')` → `/admin/index/index`，正常。
- 影响点（两项目）：`app/common/controller/Backend.php` 的 `redirect('index/login')` 与 `redirect('index/index')`；tp8 另有 `TenantBackend.php` 两处 + `tenant/Index.php`/`Index.php` 的 `redirect($url)`。
- 修复方案：在 `app/BaseController.php::redirect()` 内补 URL 构建（对齐同文件 `success()/error()` 已做的 `url($url)` 逻辑），单点覆盖全部调用点。待老板确认后落地。

## 落地：BaseController::redirect() 修复（已完成，两项目）
- 已改 `app/BaseController.php::redirect()`（rocket-admin + tp8-fastadmin 同步），补 `url($url, $params)` 构建 + `$params=[]` 归一。
- 探针验证：`redirect('index/index')` 从裸 `index/index` → `/admin/index/index.html`（`.html` 是 `url_html_suffix='html'` 的正常产物，路由会自动剥离，与 success()/error() 及 TP5 原行为一致）；`redirect('/admin/index/index')` 绝对路径原样保留。
- Layuiadmin-tp8 **不改**：其 BaseController 无 redirect() 方法，已用「绝对路径 + Index.php:96 注释约定」规避同一坑，正常工作。

## 定稿：改为方案 A（显式化），对齐 YFCMF-TP6 社区做法
- 老板觉得"基类转换怪"，调研 gitee 上的 FastAdmin TP6 移植版 **YFCMF-TP6**（gitee.com/nymondo/yfcmf-tp6）：其 `app/common/library/traits/Jump.php` 的 `redirect()` 是纯转发 `\redirect($url)`，但调用点用 `redirect(url('index/index'), [], 302, [...])` 显式构建。Layuiadmin-tp8 同理（`redirect(url('/admin/index/login'))`）。
- 最终落地（两项目同步）：
  - 基类 `BaseController::redirect()` 简化为三参纯转发 `redirect($url, int $code=302, array $with=[])`，去掉死参数 `$params` 和 URL 转换。
  - 调用点显式 `url()`：Backend/TenantBackend 的 `redirect('index/login')`、`redirect('index/index')` 改为 `redirect((string)url('index/xx', [], false), 302, [...])`；三个 Index.php 的 `$url = $url ?: 'index/index'` 改为 `$url = $url ?: (string)url('index/index', [], false)`。
- 探针验证：admin 上下文 `redirect('index/index')` → `/admin/index/index`，tenant 上下文 → `/tenant/index/index`（`url()` 自动补应用名，多应用友好）。
- 关键点：`url()` 第三参 `false` 去 `.html` 后缀；相对写法 `'index/index'` 靠 `url()` 自动补当前应用名，比硬编码 `/admin/index/index` 更通用（tenant 也能用）。

## Layuiadmin-tp8 去硬编码 /admin/（参考 rocket-admin，已全部完成）
- 背景：Layuiadmin-tp8 是 FastAdmin 的 layui 模板替代（同 rocket-admin/tp8-fastadmin 一类），不该硬编码 /admin/ 前缀，应统一相对 url() + moduleurl 机制。
- 改动（全链路）：
  1. 重定向 4 处（Backend.php denyUnauthorized、admin/Index.php 登录兜底/登出）→ 相对 url()；
  2. formAction 15 处（auth/Admin、auth/Group、auth/Rule、Category、general/Config、user/Group、user/Rule、user/User 的 add/edit）→ `(string) url('控制器/方法', [], false)`；
  3. MenuService::buildUrl：iframe 分支去 /admin/ 前缀、单层补 /index（避开 url() 单段陷阱）、末尾 `url($url, [], false)` 去后缀；
  4. CommandScaffold：`__FORM_VIEW__` → `url('$route/...', [], false)`、`__API__` → `Config.moduleurl + '/$route'`；
  5. layout.html：window.Config 注入 `moduleurl: '{:dirname(url("index/index", [], false), 2)}'`（→ /admin），uploadUrl/attachmentSelectUrl → {:url()}；
  6. 视图 84 处 `'/admin/xxx'` → `Config.moduleurl + '/xxx'`（sed 批量）；HTML 属性 10 处（href/action/src）→ {:url()}；
  7. public/assets JS 5 处（index.js 登录跳转、adminRequest.js LOGIN_URL、attachmentField.js upload）→ Config.moduleurl。
- 验证：PHP/JS 语法检查全过、模板 `dirname(url(...))` 渲染实测 → /admin、iframe 版硬编码 /admin/ 残留 0（SPA 版 setter.api 与注释除外）。
- 关键点：`url('category')` 单段会产出 `/admin/Index/category`（单段被当 action），故单层控制器必须补 `/index`；`url('/admin/xxx')` 绝对路径无后缀、`url('xxx')` 相对带 .html 后缀，故末尾统一 `[], false` 去后缀。

## Layuiadmin-tp8 iframe 版「刷新恢复」收敛为单一 hash（按主流做法）
- 原机制有两套记「当前页」：① layui 官方 hash record（location.hash，主流）；② 项目自研 ?p= 查询串（服务端首帧据此渲染，避免默认页→目标页跳变）。两者冗余。
- 收敛：删掉 ?p= 机制，回到官方纯 hash。
  - `admin/controller/Index.php`：删 PAGE_QUERY 常量 + resolveRemembered 调用，current_url/current_title 置空，menulist 直接用 homeUrl。
  - `common/service/MenuService.php`：删 resolveRemembered 方法。
  - `admin/view/index/index.html`：删 tabsPage(wbRememberPage) 写 ?p= 的 replaceState 块。
- 保留官方链路：config.js `record.url=true` + adminui dist admin.js `recordURL`（写 hash）+ index.js `openInitPage`（读 hash 恢复）。
- 行为变化：URL 从 `/admin?p=xxx#/xxx` 收敛为 `/admin#/xxx`；刷新后服务端渲染 fixedpage 默认页，前端 hash 恢复目标标签（官方行为，会多一个不可关闭的默认页标签）。
- 验证：php -l 通过、resolveRemembered/PAGE_QUERY/wbRememberPage 残留 0、record.url=true 确认开启。

## Layuiadmin-tp8 首帧「蓝色边框条闪到默认页」最终解法（纠正）
- 现象：收敛成纯 hash 后，刷新时顶部标签的蓝色高亮（layui-this）会先出现在默认页、再跳到目标页。
- 走弯路（已回退）：先后试过「标签栏 visibility:hidden + 内容遮罩 + revealIfActive + 去掉初始 watchActiveFrame」，结果标签栏跟着内页一起刷新，体验更差——方向错了。
- 根因：layui-this 是服务端预置在默认页标签的 HTML 里（`{if !$current_url} class="layui-this"{/if}`），浏览器一渲染蓝色边框条就落在默认页，要等 layui 加载 + openInitPage 才切目标页，中间几百 ms 可见。
- 最终最小改法：去掉服务端预置的 layui-this（`<li lay-id="{$home_url}" lay-attr="{$home_url}">`），让 layui element 默认激活第一个 → openInitPage 立即切目标页，两步是同一模块加载流程里的连续同步执行（几 ms），肉眼不可见。标签栏全程可见、不隐藏。老板确认「现在可以了」。
- 教训：用户要的是「改蓝色边框条」，不是「处理标签栏整体」；先搞清楚最小改动点，别把局部样式问题扩大成整块显示逻辑改造。
