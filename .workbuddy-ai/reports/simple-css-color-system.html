结论先行

  1. 这套配色的真正内核不是「颜色好看」，而是「面退后、文字前进」。 所有容器、表头、hover、激活底之间的对比度只有 1.005 : 1 ~ 1.10 : 1 —— 几乎不可见。 视觉重量被刻意全部让给文字层与主色。这是它「轻、干净、不花」的根因。
  2. 单一主色强锚定是统一性的最大来源。 #165dff 在 119 次颜色引用中占 27 次，且交互、选中、强调三种语义全部收敛到它，没有第二个蓝。
  3. 中性灰是「四档语义分工」，不是随手取的四个灰。 #f6f8fb（结构性面）→ #f4f4f5（瞬时 hover）→ #f0f5ff（激活态，带主色倾向）→ #f1f4f6（1px 分割线）。 「越靠近结构越冷，越靠近交互越带主色」—— 这是可以直接搬走的规则。
  4. 语义色一律「同色浅底」而非「实心色块 + 白字」。 状态标签走 color: 语义色 + background: rgba(同色, .1)。 但实测这套取值本身不达 AA（绿 2.20:1、橙 2.03:1、红 2.96:1）， 照搬时必须同时把文字色降到 700 档。详见 §3.3。
  5. 交互反馈有 60% 靠几何而非颜色。 菜单 hover 从「整行铺满」变成「内缩 10px 圆角胶囊」，Tab 激活用 4px 主色下划线 —— 形状与颜色双通道反馈。
  6. 最该学的反面教材：38 个色值全部硬编码，0 个 CSS 变量。 直接后果是出现了 #323639 与 #323638 这种对比度 1.001 : 1 的孪生值， 以及 #0054fe 与 #165dff 这种「肉眼同色、取值不同」的主色变体。

色彩体系解剖：8 处值得借鉴

按可迁移性排序

1.1单主色锚定 —— 27 / 119 的绝对集中度

#165dff 是文件里唯一的品牌蓝。它同时承担三种语义：

#165dff
实心强调按钮底 / 图标底
#f0f5ff
选中态浅底约 8% 主色
.8 透明度
次级实心hover / 弱化
下划线
激活指示4px 圆角条

关键在于它没有引入第二个蓝。对比 rocket-admin 现状：除了主色 #165dff， 公共基线里还留着 #4397fd（fastadmin 链接色）、#1688f1（btn-info）。 三个蓝的色差小到「看起来像没对齐」，这正是界面显脏的常见来源。

1.2中性灰的四档语义分工

这是整套体系里最可直接复用的一条规则。四个灰不是深浅梯度，而是按「离用户的远近」分工：

色值语义槽用在哪些元素色相倾向
#f6f8fb结构性面表头底色+边框、弹层标题栏、弹层底部分隔线最冷（B−R = +5）
#f4f4f5瞬时反馈侧边栏 hover、折叠菜单底、控制栏页签中性（B−R = +1）
#f0f5ff激活 / 选中菜单选中、页签激活、Tab active带主色倾向
#f1f4f61px 结构线内容区左边框、表格行分割线冷灰
可迁移规则

静止的面 → 冷而亮；被操作的面 → 带主色。 这样「当前选中」与「鼠标划过」在色相上就能区分，不必依赖深浅 —— 而深浅差只有 1.01 : 1，肉眼本来就分辨不出来。

这些数字远低于任何无障碍阈值。但把它们放在「面」这个角色上看，反而是刻意的克制： 1.03 ~ 1.10 : 1 刚好在屏幕可辨阈值附近，眼睛能感到「有一层底」，但不会被色块切割版面。 代价是灰度打印或低质量屏幕上面层会完全消失，所以这套体系必须保证「不依赖面层也能读懂」—— 它做到了，因为文字层全部达标（§2）。

1.4语义色的「同色浅底」容器化

状态标签一律写成「语义色文字 + 同色 10% 底」，而不是实心色块：

label-success
rgba(24,188,156,.1)文字 #18bc9c
label-warning
rgba(243,156,18,.1)文字 #f39c12
label-danger
rgba(247,84,68,.1)文字 #f75444
label-primary
rgba(0,0,0,.6)唯一例外

为什么值得借鉴：一个列表页同时出现「已完成 / 进行中 / 已失败」三种状态时， 实心色块方案会形成三个高饱和色块互抢注意力，页面看起来「彩虹爆炸」； 浅底方案里状态信息的视觉重量被降到与正文同级，只在需要时被扫到。 这也是为什么它能容忍页面上同时存在多个状态而不显乱。

但取值必须改

实测这三组「语义色文字 on 其 10% 浅底」的对比度分别是 2.20 : 1 / 2.03 : 1 / 2.96 : 1，全部不达 AA 4.5:1。 照搬这个模式时，文字色必须换成同色系的 700 档，例如 #128f76 / #b9760a / #c33a2b。 顺带一提：#128f76 在 simple.css 里已经存在，只是被用在了按钮 hover 底上，没用在标签文字上。

1.5状态图标：让颜色退位，让形状承担区分

弹层的成功 / 警告 / 信息三种状态图标（.layui-layer-ico0/1/3） 被统一压成同一个 #165dff 圆形徽标，仅靠 FontAwesome 字形区分：

  • \f058 实心对勾 —— 成功
  • \f12a 感叹号 —— 警告
  • \f00c 空心对勾 —— 信息

效果：弹层里不会出现红 / 黄 / 蓝三个色块；对红绿色觉障碍用户， 信息由字形而非颜色承载，可辨识性反而更高。这是「颜色不是唯一信息通道」原则的正面案例， 也是整份文件里唯一符合无障碍色彩规范的一处设计。

1.6弱化边框，用明度和留白分层

三条具体手法：

  • border-color: transparent !important 被批量用在工具条按钮、侧栏、logo、页签上 —— 该有边的地方主动去掉边。
  • 弹层标题栏与内容区之间没有 1px 描边，靠 #f6f8fb → #fff 的明度差分层。
  • 表格只保留纵向分割线：border-left-width:0; border-right-width:0，横线交给 #f1f4f6（1.10 : 1）。

效果：版面里没有一堆灰线把内容切碎，信息区看起来更「整」。 代价是必须靠留白和字重来建立层次 —— 这套配色与「大内边距 + 表格化排版」是配套的，单独抄颜色不会有效果。

1.7交互反馈有 60% 交给几何

最典型的是侧边栏菜单项：

原文手法

静止态：整行铺满、无圆角。
hover 态：padding-left:5px; margin:0 10px; border-radius:8px; background:#f4f4f5 —— 变成内缩 10px 的圆角胶囊。
激活态：同几何 + color:#165dff; background:#f0f5ff。

在 20 项以上的长菜单里，「鼠标在哪」和「当前在哪」是两种必须区分的状态。 纯靠底色区分时，#f4f4f5 与 #f0f5ff 的差异只有 1.01 : 1，几乎不可辨； 加上「内缩 + 圆角」这个几何变化后，两种状态立刻分得开。 页签激活用 ::after 画 4px 主色圆角下划线，是同一个思路。

1.8深浅双态共用语义槽位，主色恒定

深色主题不是另起一套配色，而是把同一批槽位映射到暗色梯度，品牌主色保持不变：

hover / 条纹行#f4f4f5#404040—

面板标题栏#fff#3a3a3a—

七个不能照搬的坑

含可验证的实测证据

3.1零 CSS 变量，38 个色值全部硬编码

全文件 911 行，0 个自定义属性。改一次主色需要全局替换 27 处。 这是「可借鉴性」上最大的减分项 —— 它的配色思路值得抄，实现方式不值得抄。

#0054fe 与 #165dff 的对比度只有 1.093 : 1 —— 肉眼完全同色， 但取值不同。这种「看不出差别的不一致」正是设计系统最该消灭的噪音。

3.3语义色当文字时不达 AA（已在上文给出实测值）

这是最容易在照搬时踩进去的坑：模式对，取值错。 浅底方案本身是优秀的，但 #18bc9c / #f39c12 这类 500 档饱和色 天生不适合做小字号文字。迁移时必须成对替换（文字降档 + 浅底保持 10%）。

3.4深色态主色对比度崩到 2.0 : 1

深浅两态共用 #165dff 这个决定在浅色态是对的（5.19 : 1）， 在深色态却是硬伤（2.00 ~ 2.91 : 1）。正确做法是深色态用一档提亮的主色， 而不是「为了品牌一致硬扛」。

3.5!important 占声明数 35%

117 处 !important / 约 337 条声明。这是为了压制 FastAdmin 基线的必然结果， 但也意味着后续任何覆盖都要继续加 !important，样式表会不可逆地劣化。 rocket-admin 的 skin-white.css 有同样倾向，值得警惕。

3.6逐字重复的规则

第 732–738 行与第 740–746 行完全一致（已用 diff 验证）：

body.sdtheme-white .treeview-menu > li.active > a { color:#165dff; background:#f0f5ff; margin:0 10px; border-radius:8px; padding-left:15px }

同类问题还有：#f0f5ff 相关的激活态规则散落在 6 个互不相邻的位置。 缺少分层，是「补丁式演进」的典型痕迹。

3.7语义色被主色污染

第 461 行：.sdtheme-body .text-success { color: #165dff } —— 把「成功」刷成了蓝色。这是 bug 不是设计取向，会让「成功」与「链接」在语义上无法区分。 rocket-admin 已修正为 #18bc9c，不要回退。

按落地优先级
SCENE 01

状态标记：订单状态 / 设备在线离线 / 审核结果

借鉴
§1.4 同色 10% 浅底 + 语义色文字；文字色改用 700 档（#128f76 / #b9760a / #c33a2b）。
效果
一屏 20 行数据不再「彩虹爆炸」，扫描速度明显提升；灰度打印时仍能靠文字色与文案区分，不依赖底色。

IoT 设备列表、工单列表、审批流、日志级别标记。

借鉴

效果
表头「退后」、数据「前进」，长表格横向扫描不累；行 hover 用主色 5% 而非灰，能明确提示「这一行可操作」。
适用
所有 Bootstrap-Table 列表页。
SCENE 03

侧边导航 / 多级菜单

借鉴

效果
长菜单里「鼠标在哪」与「当前在哪」靠几何 + 色相双通道区分。这一条不能只抄颜色，几何必须一起抄。
适用
20 项以上的后台侧栏、树形菜单、多级 Tab。
SCENE 04

借鉴
#f6f8fb 标题栏、标题与内容间不加 1px 描边（靠明度分层）、次要按钮用 #f6f8fb 浅底而非纯白。
效果
弹层与页面层次清晰但不「厚重」；确定 / 取消的主次关系靠底色差异一眼可辨。
适用
FastAdmin 的 layer 弹层、表单弹窗、确认框。
SCENE 05

深浅双主题产品

借鉴
§1.8 槽位化思维 —— 结构不变、只换梯度、品牌主色恒定。
效果
主题切换不破坏品牌识别。但必须修正主色在深色态提亮一档，否则链接不可读。

SCENE 06

BI 看板 / 数据大屏

借鉴
中性灰容器 + 单一主色 + 语义色只用于异常（§1.1 + §1.4）。
效果
在信息密度高的看板上，「颜色即优先级」—— 满屏中性灰里出现一个橙色，用户会立刻看过去。若日常数据也用高饱和色，异常就失去了信号价值。
适用
Dashboard、设备态势页、运营看板。
适用边界

这套配色的舒适区是「工具型、长时间注视、信息密集」的界面 —— 它通过压低一切非文字元素的对比度来换取耐看。 不适合营销落地页、活动页、产品官网首页：那些场景需要大色块与高饱和对比来制造冲击力， 用这套配色会显得寡淡、缺乏行动召唤力。判断标准很简单：这个页面是让人「读」还是让人「动」。

落到 rocket-admin 的具体建议

优先级动作说明
P1 抽 token 层 在 skin-white.css 顶部加 :root 变量（--brand-500 / --brand-50 / --neutral-surface / --neutral-hover / --neutral-active / --line），把现有硬编码替换为变量引用。这是simple.css 最该学、却没做的一件事。
P1 语义色标签成对降档 若引入「同色浅底」标签，文字色用 #128f76 / #b9760a / #c33a2b / #165dff，浅底保持同色 10%。不要直接抄 #18bc9c / #f39c12 做小字。
P2 收敛多余蓝色 #4397fd（fastadmin 链接基线）、#1688f1（btn-info 基线）与主色 #165dff 色差过小。若要统一需评估影响面 —— 注意 .text-primary 保持 #444c69、.text-info 保持 #1688f1 是有意为之的基线决策，不要误改。
P2 菜单 hover 加几何变化 把侧栏 hover 从「只变底色」升级为「内缩 + 圆角 + 变底色」。这是投入产出比最高的一处改动。
P3 核对深色态（若有） skin-white.css:719-723 已有 darktheme 分支（表头 #262626）。若后续要启用，主色需提亮一档。
