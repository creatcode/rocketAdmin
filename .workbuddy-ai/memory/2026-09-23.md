### 根因（实测确认，架构性）
- `.fixed` 的全部作用是顶栏/侧栏 `position:fixed` + `.content-wrapper{padding-top:50px}`，**差异只在外层页面滚动时才可见**。

  注入 2000px 高元素后 `bodyScrollH` 仍 = `winH`（708），溢出被 `.wrapper` 裁掉，`canScroll:false`。
- 故开关能正确切 class（`headerPos` `fixed↔relative`）但 `headerTop` 恒为 0 → **零可见效果**。
- 其唯一可见影响是压制盒子布局（`fastadmin.css:130` `.fixed.layout-boxed .wrapper{max-width:100%}`）。

### 改动（用户判断成立 → 改为单向派生，而非两个互斥按钮）
- `control.html`：删除「固定布局」的 `.lc-row`（保留「盒子布局」）→ 面板开关 **7 → 6** 项。
- `index/index.html:7`：`{:$Request.cookie.fixed!='0'?'fixed':''} {:$Request.cookie.layout_boxed?'layout-boxed':''}`
  → `{:$Request.cookie.layout_boxed?'layout-boxed':'fixed'}`（**二选一，不再有独立 fixed cookie**）。
- `index.js`：删除 `[data-layout='fixed']` 绑定；盒子布局绑定内改为 `toggleClass('fixed', value !== 1)`；

### 既有 bug：reload 后 URL 重复 index.php → cookie 失效
- 现象：`location.reload()` 后 URL 由 `/index.php/admin/dashboard` 变为 `/index.php/index.php/admin/dashboard`。
- 后果：`createCookie` 的 path = `Config.moduleurl`（`/index.php/admin`），新 URL 前缀不匹配 → **cookie 不被发送** →
  `Index.php:37-43` 读不到 → `Config::set('rocket.*')` 不执行 → 菜单/布局不生效。
- 实测链路：
  | 步骤 | URL | cookie | 菜单 class |
  |---|---|---|---|
  | 0 初始 | `/index.php/admin/dashboard` | — | `sidebar-menu` |
  | 1 点击瞬间 | — | `show_submenu=1` 写入成功 | — |
  | 2 reload 后 | `/index.php/index.php/admin/dashboard` | 空 | 未变 |
- 归因：`git stash` 暂存全部改动后重测，原始状态同样复现 → **既有问题，非本次改动引入**。
- 拼接嫌疑：`fast.js:96` `url = Config.moduleurl + "/" + url`。
- 影响：所有「写 cookie + `location.reload()`」的开关（`multiplenav`、`show_submenu`）。
- 可选修法：修 URL 拼接，或把 `createCookie` 的 path 改为 `/`（作用域放大，需评估）。

## 新增无操作自动登出（按秒配置）

### 需求与迭代
用户要求做无操作自动登出；实测时发现按**分钟**配置不便测试（最小 1 分钟），用户建议改为**按秒**，采纳 —— 正式值 `1800`（30 分钟），测试时用 `10`。

### 改动（2 个文件 + 配置）
- `config/rocket.php`：`auto_logout`（**秒数**，0 = 不启用，默认 1800）。
- `app/admin/controller/Index.php`：`assignconfig('autoLogout', (int)config('rocket.auto_logout'))`。
- `public/assets/js/backend/index.js`：index 初始化末尾加计时逻辑（约 45 行）。

### 关键设计
- **iframe 内事件不会冒泡到外层**（这是本功能最大的坑）：外层 `$(document).on('mousemove keydown click scroll', resetIdle)` 只覆盖顶栏/侧边栏；
  内层改用**同源 `contentDocument` 直接绑定**（`doc.__idleBound` 标记防重复绑定），并用 `setInterval(2000)` 兜住 addtabs 动态新增的 iframe。
  —— 好处是**不必改 `backend.js` 等公共库**。
- `resetIdle` 做 1 秒节流，避免 mousemove 高频重建定时器。
- 提醒提前量 `min(60, auto_logout * 0.2)` 秒（30 分钟 → 60 秒；10 秒 → 2 秒），经 `Toastr.warning` 弹出。
- 到时 `location.href = Backend.api.fixurl('index/logout')`；`Index::logout()` 是「GET 返回自动 POST 表单」机制，地址栏会先出现 `/index/logout` 再完成登出。

### 实测（`auto_logout = 10` 秒，headless Edge + CDP）
| 时刻 | 状态 | 结论 |
|---|---|---|
| t=0 | `Config.autoLogout = 10` | 按秒配置生效 |
| t=5 | 在 iframe 内 dispatch mousemove | 已注入 |
| t=9 | 仍在 `/dashboard` | **iframe 活动成功重置计时器** ✓ |
| t=14 | toast「已长时间无操作，将在 2 秒后自动退出登录」 | 提醒正常 ✓ |
| t=18 | 已跳转 `/index/logout` | **自动登出成功** ✓ |

（首轮 1 分钟配置的测试同样通过：t=80 仍在线证明 iframe 重置生效，t=130 已登出。）

### 备注
- 提醒的 toast 约 5 秒后自动消失，探测时机不对会读不到（本轮踩过，非 bug）。

### 补充：scroll 覆盖盲区修复（同日）
- **盲区**：`$(doc).on('mousemove keydown click scroll')` 的 `scroll` 走**冒泡**，而**内部滚动容器的 scroll 不冒泡**
  （bootstrap-table 的 `.fixed-table-body{overflow-y:auto}`、AdminLTE 侧边栏 slimscroll）→ 用户滚动浏览时不计入操作，
  可能被误判为无操作而提前退出。
- **修法**：`$(doc).on('mousemove keydown click', resetIdle)` + `doc.addEventListener('scroll', resetIdle, true)`
  （捕获阶段覆盖全部后代滚动；jQuery 不支持捕获，故必须用原生 API）。
- **实测**（`auto_logout=5`）：注入 `overflow-y:auto` 容器每 1.5 秒滚动一次 → 9 秒内**始终不退出**；停止滚动后 5 秒正常退出。

### 补充：事件覆盖补全 + 多标签页同步（同日）
- **事件盲区**：原只监听 `mousemove keydown click scroll`。补齐为 `mousemove mousedown click keydown input`（jQuery）
  + `scroll`（捕获阶段）+ `wheel`／`touchstart`（passive）。`mousedown` 覆盖右键（**右键不触发 `click`**）；
  `input` 覆盖粘贴与输入法文本输入；`wheel` 覆盖内容不足一屏时**不产生 `scroll`** 的情况。
- **多标签页同步**：`resetIdle` 里 `localStorage.setItem('idleActivity', now)` 广播，`window` 监听 `storage` 事件续期。
  **关键**：监听端只 `resetTimer()`、**不再广播**，否则 A↔B 互相触发会形成死循环。
- **实测**：右键／滚轮／文本输入均能重置计时器；停止交互后按配置时长正常退出；超时后 URL **仍停在后台页**且弹窗出现，
  点"确定"才跳登录页。

### 补充：弹窗出现时即完成服务端登出（隐藏 iframe）
- **用户澄清的语义**：弹窗出现时**会话已经结束**，只是页面还没跳转；点"确定"或刷新都回登录页。
- **为什么不能"前端直接清 cookie"**（用户提议，已否）：`config/cookie.php` 的 **`httponly => true`**，实测 `document.cookie`
  只剩 `thinkphp_show_page_trace`，**token 与 PHPSESSID 都读不到**，清不掉；更根本的是 FastAdmin 登录态载体是
  **服务端 token 表**（`Auth`：`Token::get($token)`／`Token::delete($this->_token)`），只清客户端 cookie 不删服务端记录，
  会话实际仍有效、cookie 一恢复就能复活。→ **必须走服务端登出**。
- **实现**：`onIdle` 里追加 `$('<iframe>').css('display','none').attr('src', Backend.api.fixurl('index/logout')).appendTo('body')`，
  静默走完「GET → 页面内自动提交表单 → POST」的登出流程；弹窗只做告知，页面暂不跳转。
- **实测**：超时前 `fetch('index/index')` 返回 `<title>首页</title>`；超时后返回 `<title>温馨提示</title>`（"请登录后操作"）

### 多标签页同步：真实双标签页验证通过
- **做法**：A 标签登录后装 `storage` 探针（`__hits`）且此后不再操作；B 标签写 `localStorage.idleActivity` 三次 →
  **A 收到 3 次 storage 事件** ✓，A 的计时器随之重置（B 在操作时 A 不会超时）。
- **踩坑**：**不能用 `about:blank` iframe 模拟"另一个标签页"** —— 它的 **origin 是 `null`（不继承父页面）**，
  localStorage 不共享，写它**不会**触发父页面的 storage 事件（实测探针为 0）。要验证跨标签页通信必须用**真实第二个 tab**
  （`PUT /json/new` 创建 + 独立 WS 连接）。
- **headless 多标签页注意**：新建 tab 会抢焦点，被切到后台的 tab 其 `setTimeout` 会被节流 —— 验证「定时器是否被续期」时
  要留意这个干扰；验证「事件是否收到」则不受影响（本次即采用后者）。

### 兜底缺口（按优先级）
1. **定时器可信度**：`setTimeout` 在 Chrome 后台标签常规节流下仍会触发，但 **Freeze / Tab Discard / iOS 挂起期间根本不跑** → 回到前台不会立即判定。修法（+4 行）：记录 `lastActive` 墙钟时间戳，`visibilitychange`／`pageshow` 时复核 `Date.now() - lastActive >= idleLimit` 则登出。**上一轮删 `visibilitychange` 删早了。**
2. **触摸端**：`mousedown` 依赖浏览器合成 mouse 事件；**滑动只在能产生 `scroll` 时才被捕获**，`overflow:hidden` 区域内的滑动（图片预览、自定义拖动、地图）零事件 → 被误判无操作。修法：`mousedown` → `pointerdown`（原生统一鼠标/触摸/笔，净 0 行）+ 补 `touchstart`。
3. **架构缺口：直接打开内页 URL（书签 / 分享链接）→ 没有外层框架 → 水印和自动登出都不生效**。内页走 `layout/default.html`（无侧边栏）+ 各自 controller 的 js，`index.js` 的 index 分支不执行。修法：逻辑挪到 `backend-init.js`（`require-backend.js:9` 的 include 列表 → 所有后台页都加载），条件用 `window.self === window.top`（同时覆盖外层框架与独立打开的内页，排除框架内 iframe 避免重复绑定）；配置需回到 `Backend::initialize()`（见上，位置反复过）。

### 关键实测结论（推翻方案原文，已写入 MEMORY.md）
1. **curl 在本机完全不可用**：`curl.cainfo` 为空 → 访问任何 HTTPS 都 `SSL certificate problem: unable to get local issuer certificate`。`CURLOPT_PROXY=''` 也一样失败。
2. **Guzzle 救不了**：Guzzle 7.4.5 默认 handler 就是 curl（实测 `cURL error 60`），且**不自带 `cacert.pem`**（早期版本有，现已移除）。只有强制 `StreamHandler` 才通——那本质就是「用 PHP stream 套了个壳」。且它是 `easywechat` 的**传递依赖**，不在 `composer.json` 的 `require` 里，当正式依赖用要改 composer.json/lock 并跑 composer install。结论：**用原生 `fopen` + `stream_copy_to_stream`**（实测 1775 bytes + sha256 一致，流式不占内存）。
3. **PHP 的 stream wrapper 不读 `http_proxy` 环境变量** → 之前「代理导致本地 502」是**误诊**（真实原因是 mock 服务已死 + `curl -o /dev/null` 在 Git Bash 下的写错误）。同理「GitHub 不可达」也是同一测量失误——**GitHub 一直可达**。
4. **GitHub `assets[].digest` = `sha256:<hex>`，实测 22/22 非空** → GitHub 源白拿真实校验和，G7 零成本闭环。Gitee 无此字段。
5. `assets[].size` 存在（Gitee 无）；实测 `vuejs/core` 的 `assets` 为**空数组** → 回退 `zipball_url` 是**必需路径**。
6. `tag_name` 两边都带 `v`（`v2.101.0`/`v4.8.3`）→ 必须 `ltrim($tag,'vV')` 后 `version_compare`。
7. `openssl.cafile` 虽为空，但 **PHP stream 访问 GitHub 实测成功** → `verify_tls=true` 可行。
8. **`Fast.api.ajax` 不带 token、也不读 `__token__` 响应头**（那逻辑在 `require-form.js` 的表单提交路径）；`$this->token()` 不是自动校验，而是被各 CRUD 控制器显式调用的。
