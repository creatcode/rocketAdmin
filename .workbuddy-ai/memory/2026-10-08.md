## 调研：FastAdmin 官方插件在 TP6 下的兼容断点（用户提问，方案未落地）
- easyaddons **已覆盖**：5 个旧命名空间别名（`think\Addons`、`think\addons\{Service,Controller,AddonException,Route}`）、TP5 常量（DS/EXT/ROOT_PATH/APP_PATH/CONF_PATH/RUNTIME_PATH）、文件函数（rmdirs/copydirs/is_really_writable/var_export_short）、**目录映射**（`getCheckDirs()` = `application→app`、`public→public`；`assets→public/assets/addons/<name>/`；`getGlobalFiles()` 里 `str_replace('application'.DS,'app'.DS)`）、纯净模式（合并后删除插件目录这三个文件夹）、`hook()` 桥接 + `Event::trigger` 回传引用参数。
- **实测断点**（`php -r` + `initialize()` 后逐个 try/catch）：
  - `think\Db::name()` → `Error: Call to undefined method think\Db::name()`（TP6 的 `think\Db` 是 DbManager，不是 facade）
  - `think\Config::get()` / `think\Env::get()` / `think\Cache::get()` / `think\Log::write()` → `ErrorException: Non-static method ... should not be called statically`
  - `think\Session::get()` → `Error: Call to undefined method`
  - 类不存在：`think\Loader`、`think\Hook`、`think\Url`（TP6 已移除）
  - ⇒ **原版插件里所有 TP5 静态调用都会 fatal**，这是"装上但用不了"的头号原因；反射确认这些类名在 TP6 里是框架真实类（`vendor/topthink/framework/src/think/*.php`），不是别名。
- 模板层：`$Think.config.*` 在 TP6 模板里编译成 `''`（见上文），插件视图大量该写法会**静默失效**（不报错，只是空白）。
- **不能用全局 class_alias 修**：`think\Db`/`think\Config` 等类名已被 TP6 真实类占用 → "Cannot redeclare"，且会波及框架自身。
- 方案方向（未落地）：① 安装期代码适配器（改写 `use think\X;` → `use think\facade\X;`、`Hook::*` → `Event::*`、模板 `$Think.config.` → `config(`，改写前备份 + 出报告 + 可回滚）；② 安装前静态体检（只报告不改，装之前就知道能不能用）；③ 兼容性台账 + 市场侧标注。优先级 P0=体检、P1=改写、P2=台账。
- 不可自动兼容的边界：`think\Loader` 动态类加载、TP5 路由规则、依赖 TP5 `where` 参数顺序、深度 Hook 用法 → 只能人工适配或标记不支持。
- 注意：tp8-fastadmin 是 TP8，facade 化程度与 TP6 相同 → 断点一致，适配器可两版共用。
- **补充实测（关键简化）**：
  - **只要把 `use think\X;` 指向 facade 即可**：`think\facade\{Db,Config,Env,Cache,Log,Session}::xxx()` 静态调用全部成功 → 插件业务代码一行都不用动，本质是「import 重定向」而非「代码改写」。
  - 扫描性能（本机 Windows）：遍历 `vendor/` 3612 个 PHP 文件（15MB）耗时 3.1s；**只读文件头 8KB 与全量读几乎同耗时（3.16s vs 3.13s）** → 瓶颈是文件遍历次数，不是文件体积。跳过 `vendor/`、`node_modules/`、`assets/` 后，插件业务目录（几十~两百个 PHP）耗时 < 0.3s。
- 路线选择（待用户定）：**A** 本地轻量改写（只改 `use` 行）；**B** 服务端预适配出 TP6/TP8 版、用户端零改写（体验最好）；**C** 只体检 + 人工适配台账（零风险）。建议 C 打底 + B 为主 + A 兜底。
- **前提更新（2026-10-08）：本系统准备做成开源系统**；且**FastAdmin 官方不做 TP 内核升级**（这正是本项目的存在理由）→ 官方插件生态会长期停留在 TP5，第三方也不会为移植版专门适配，所以「兼容存量插件」是**核心竞争力**而非过渡功能。策略随之调整：

## 调研（2026-10-08）：用 Gitee/GitHub 当插件源的实际可用性（本机 PHP stream 实测）
- **GitHub raw 在本机完全不通**：`raw.githubusercontent.com/...` → `failed to open stream: operation failed`。国内环境直接排除。
- **Gitee raw 程序可下载**：`https://gitee.com/<owner>/<repo>/raw/<branch>/<path>` → **302 Found**，Location 指向 `raw.giteeusercontent.com/...?metadata=...&signature=...`；**必须跟随跳转**（`follow_location=1`）才拿到内容 —— 实测跟随 5 次内拿到 `200 OK` + 3475 字节真实内容。
- **关键坑：302 的签名有时效**（metadata 里带 `expire_at`）→ **不能把跳转后的直链缓存/写进清单**，每次都要从原始 URL 请求、由程序跟随跳转。
- Gitee 有反爬/防盗链机制（图床外链受限是已知事实）→ 高频程序化访问存在被限流或要求验证码的风险；单次访问实测正常。Release 附件（`/releases/download/<tag>/<file>`）未实测。
- **修正（用户指出后实测确认）**：Gitee 的**包文件下载会被拦截** —— `gitee.com/<o>/<r>/repository/archive/master.zip` 返回 **47KB HTML「下载仓库」页**（含 `验证码` / `验证` / `登录` / `captcha` 关键词）；Release 的 asset 是 Gitee 自动生成的 `archive/refs/tags/*.zip`，走同一拦截路径。⇒ **Gitee 只能放清单类小文本，不能放包**。
- **关键发现：Gitee 的 git 协议端点不被拦** —— `git ls-remote https://gitee.com/fastadminnet/fastadmin.git` 正常返回分支列表、无验证码；Gitee API v5（`/api/v5/repos/.../releases`）也正常返回 JSON。
- 通道可用性汇总：Gitee raw 小文本 ✅（需跟随 302）/ Gitee 仓库 zip ❌ / Gitee Release 附件 ❌ / **Gitee git 协议 ✅** / Gitee API ✅ / GitHub raw ❌（国内不通）。
- **结论修正（实测，推翻上一条的 git 方案）：Gitee raw 支持二进制与大文件，且不需要 git** ——
  - `gitee.com/mirrors/redis/raw/unstable/src/server.c` → **200 + 316102 字节 / 1.78s**
  - `gitee.com/fastadminnet/fastadmin/raw/master/public/assets/img/logo.png` → **200 + image/png + 20954 字节**（PNG 魔数 `89504e47`）
  - ⇒ 关键区别：**`raw/<branch>/<path>` 是"读取仓库已有文件"，不拦；只有 `repository/archive/*.zip`（动态打包）被拦**。
  - 所以插件包可直接作为**普通文件提交进仓库**、用 raw 下载：**纯 HTTP、不依赖 git 命令、免费**。
- 遗留风险：① **MB 级 zip 未实测**（309KB 已通过）；② Gitee 对高频 raw 访问的限流阈值未知；③ zip 反复提交会让 Git 仓库膨胀（历史版本占用），建议固定文件名 + 覆盖式提交。
- 系统侧仍应**不绑定平台**：清单 `download` 字段写完整 URL，raw / 对象存储 / 自建目录都能直接套用。
- **GitHub 全端点不可达（2026-10-08 实测）**：`github.com`（22.8s 超时）、`api.github.com`（8.9s）、`raw.githubusercontent.com`（2.8s）、`codeload.github.com`（0.27s）、`objects.githubusercontent.com`（0.32s）**全部 failed to open stream**。⇒ 国内环境 GitHub 作为插件源不可行，默认用 Gitee；GitHub 只能作为"网络能通的人自选"的备选（源地址可配置）。
- 官方市场：自建源后可不再依赖 `api.f1astadmin.net`；但现有机制只认官方市场 API 协议（`/addon/index`、`/addon/download`、`/addon/valid`），**静态清单源需要新增一种源类型**（新配置项 + 取包适配器），两种源可共存/切换。

## 修复（2026-10-08，沙箱 HTTP 实测发现）：升级时 SQL 导入失败
- **现象**：沙箱内走真实 HTTP 接口升级（`addon/upgrade`）→ `code=0 SQL导入失败：Call to a member function exec() on bool`；版本已变但 `state` 异常变成 1。
- **根因**：easyaddons `Service::importsql()`（`Service.php:461`）用 `Db::getPdo()->exec($sql)`，而 **TP6 是惰性连接** —— 无活动连接时 `Db::getPdo()` 返回 `false`（实测：无连接 → `boolean(false)`；事务中 → `object`；且 `think\DbManager` 根本没有 `getPdo` 方法）。`Service::install()` 内有 `Db::startTrans()` 已建连接所以正常；`Service::upgrade()` **无事务**，`importsql()` 是首次触碰数据库 → `getPdo()` 为 false → `exec()` on bool。
- **连带影响**：异常中断 `upgrade()`，其后的 `set_addon_info()` 未执行，而解压已把包内 `info.ini`（`state = 1`）覆盖上去 → 升级后插件被「意外启用」。
- **最终修复（根因，用户确认 easyaddons 由自己维护可直接改）**：`vendor/creatcode/easyaddons/src/addons/Service.php:461` 的 `Db::getPdo()->exec($templine)` → **`Db::execute($templine)`**。控制器侧的预热绕过已撤除。
- **跨版本正确性已核实**（本机无 PHP8，跑不了 TP8，改为对比两版框架源码）：`PDOConnection::getPdo()` 在 TP6/TP8 **逐字一致**（`if (!$this->linkID) return false;`）→ 两版都会犯同样的错；`PDOConnection::execute(string $sql, array $bind = []): int` 两版签名一致且都会自动建连接；`DbManager::__call` 两版实现相同（转发到 `connect()`）。故该改法对 TP6/TP8 均成立。
- 验证：撤除预热后重跑「装 1.0.0 → 禁用 → 升级 0.9.0」全部正常（`0.9.0 state=0`，SQL 导入无异常），证明是 `Db::execute()` 生效而非预热兜底。
- **验证（沙箱 + 真实 HTTP 接口，非 CLI 直调）**：安装 `code=1 安装成功`(3.1s) → 禁用 → 升级 0.9.0→1.0.0 `code=1 操作成功`(2.6s，state 正确保持 0) → 启用 → 卸载（目录/表/菜单全清）。真实项目零污染（`SANDBOX ONLY` 标记数 = 0）。
- **沙箱实测方法（可复用）**：`fastadmin-authenticated-page-probe` skill —— 只拷 `app/config/extend/route/addons/kernel/public/vendor` + `think` + `.env`（约 98M，**不要拷 runtime**）；沙箱内改 `Addon.php` 加 `$noNeedLogin/$noNeedRight = ['*']` 并把超管判断改 `if (false)`，带 `// SANDBOX ONLY` 标记；`php -S 127.0.0.1:8898 -t public` 用 `run_in_background` 起；curl 驱动时**必须带 `X-Requested-With: XMLHttpRequest`**，否则拿到 HTML 而非 JSON。
